# Mid-fi Design Tickets — Mission & Gamification

_อัปเดต 2026-08-06 · อ้างอิง `features/gamification/ux-gamification.md` + `features/gamification/prd-dev.md` v1.0_

**แบ่ง 2 ใบ**
- **T1** — flow หลักทั้งหมด ตั้งแต่หน้าภารกิจ จนของถึงมือ (Mission → Reward)
- **T2** — จุดที่ระบบเข้าหาผู้ใช้ (banner · icon · popup ภารกิจสำเร็จ)

**เปลี่ยนจากรอบก่อน**

## 🎫 T1 — Mid-fi: Mission flow ทั้งเส้น (หน้าภารกิจ → รับของ)

| | |
|---|---|
| **Type** | Design Task |
| **Priority** | High |
| **Fidelity** | Mid-fi (โครงหน้า + ลำดับข้อมูล + copy จริงเท่าที่มี · ไม่ทำ visual design) |
| **Blueprint** | `features/gamification/ux-gamification.md` §2 §3 §4 §5 §6 |

### Description

ออกแบบ mid-fi ของเส้นทางหลักทั้งเส้น ตั้งแต่ผู้ใช้เข้าหน้าภารกิจ เลือกภารกิจ ทำจนครบ กดรับรางวัล จนถึงปลายทางของรางวัลทั้ง 3 ชนิด — พร้อมทุก state ที่ผิดทาง

**เงื่อนไขพิเศษของรอบนี้:** ไม่มี onboarding ดังนั้น **หน้าจอต้องอธิบายตัวเองได้** (BP-10) เงื่อนไข · progress · รางวัล · โควตา · อายุรางวัล ต้องอ่านรู้เรื่องจากหน้าเดียวโดยไม่มีใครสอนมาก่อน

### Acceptance Criteria

**หน้าภารกิจ**
- [ ] **AC1** Mission card แสดงครบ 5 อย่างตามลำดับสายตาใน §4.3 — รางวัล → เงื่อนไข 1 บรรทัด → progress + หมุด → เหลืออีกกี่วัน → โควตาคงเหลือ
- [ ] **AC1b** Progress มี **3 รูปแบบ** ตามกลุ่มภารกิจ (prd §6.0 · MT-02) — VOLUME ขั้นล่าง `X/Y` + 3 หมุดชนิดเดียวกัน · VOLUME ขั้นบน `X/Y` เส้นเดียว · **FREQUENCY 2 เส้นแยกกัน** (จำนวนงวด + Jidrid) · ต้องมีการ์ดตัวอย่างครบทั้ง 3 แบบ
- [ ] **AC2** `MSN-201` แสดงการเรียง 4 กลุ่มตาม §4.2 มีการ์ดตัวอย่างครบทุกกลุ่ม รวมกลุ่ม "ของหมด/หมดอายุ" ที่แสดงแบบ disabled **ไม่ใช่ซ่อน**
- [ ] **AC3** `MSN-200` มี **2 tab เท่านั้น** — ห้ามมี tab รางวัล (MECH-05)
- [ ] **AC4** ไม่มีปุ่ม/ลิงก์ที่ชี้ไปหน้า onboarding หรือหน้าวิธีใช้งานที่ยังไม่มี (ผลของ D-06)

**รายละเอียดภารกิจ**
- [ ] **AC5** `MSN-210` วางโควตา · **อายุของรางวัล** · เงื่อนไข ไว้ **เหนือ CTA** (BP-02) — อายุรางวัลต้องอยู่ที่นี่เพราะไม่มี onboarding มาบอกก่อนแล้ว (§2.2)
- [ ] **AC6** `MSN-210` มี CTA เดียว แสดงครบ **5 สถานะ** ตาม §4.4 — ไปทำภารกิจ / รับรางวัล / รับแล้ว / หมดแล้ว / หมดอายุ
- [ ] **AC7** สถานะ "รับแล้ว" มีลิงก์รองไปยังปลายทางของรางวัลชนิดนั้น — NokPoint / My Coupon / LINE OA ต้องเห็นครบทั้ง 3 กรณี
- [ ] **AC8** `MSN-210` อธิบายเงื่อนไขภารกิจได้ครบโดยไม่ต้องพึ่งหน้าสอน (BP-10)

**Claim**
- [ ] **AC9** `MSN-310` แสดง **ที่อยู่ที่มีอยู่แล้วเป็นค่าตั้งต้น** และมีทางแก้/เพิ่มที่อยู่ในขั้นตอนเดียวกัน
- [ ] **AC10** `MSN-310` วางเงื่อนไข (สละสิทธิ์ถ้าติดต่อไม่ได้ · หมดแล้วหมดเลย ไม่แลกเป็นเงินสด) **เหนือปุ่มยืนยัน** (BP-06)
- [ ] **AC11** `MSN-311` แสดง error ระดับ **field** ไม่ใช่ก้อนเดียวรวมบนสุด
- [ ] **AC12** `MSN-330` มี 3 variant ตาม §4.5 · variant `PHYSICAL` บอก **ขั้นตอนถัดไปที่เกิดนอกแอป** + **หมายเลขอ้างอิงคำร้องที่ copy ได้** + **ปุ่มไป LINE OA** (BP-07, BP-09)
- [ ] **AC13** `MSN-302` มี state สำรองกรณี **claim สำเร็จ แต่ redirect ไป NokShop ไม่ได้** — บอกว่าคูปองออกให้แล้วและไปหาได้ที่ไหน (BP-08)
- [ ] **AC14** ปุ่ม claim มี state loading ที่ล็อกไม่ให้กดซ้ำ
- [ ] **AC15** **ไม่มีตัวเลขวัน/ระยะเวลาที่ยังไม่ยืนยันปรากฏในหน้าจอใดเลย** (BP-09 · SLA-01)

**System states**
- [ ] **AC16** ทุก state ใน `9xx` มี CTA อย่างน้อย 1 ปุ่มพาออกไปหน้าที่ทำอะไรต่อได้ (BP-01) — ไม่มีหน้าไหนเป็นทางตัน
- [ ] **AC17** `MSN-900` ตอบ 2 คำถาม: *ทำไมว่าง* และ *ให้ทำอะไรต่อ* (BP-03)
- [ ] **AC18** `MSN-911` ระบุชัดว่า **สิทธิ์ยังไม่หาย** (BP-04)
- [ ] **AC19** แยกภาษาและ CTA ของ error 2 ประเภท (BP-05) — ระบบผิด (`910/911`) ให้ "ลองใหม่" · เงื่อนไขไม่ผ่าน (`920/921/922`) ให้เหตุผล + ทางอื่น **ห้ามใช้ pattern เดียวกัน**
- [ ] **AC20** `MSN-922` มีทางไปปลายทางครบ 3 แบบตามชนิดรางวัล

**ทั่วไป**
- [ ] **AC21** ไม่มีคำว่า "tier" ปรากฏในหน้าจอใดเลย (MECH-02)
- [ ] **AC22** มี state map 1 หน้า แสดงว่าแต่ละ state ออกไปไหนได้ (§3.4)
- [ ] **AC23** ทุก frame ตั้งชื่อด้วยรหัส `MSN-xxx`

## 🎫 T2 — Mid-fi: Entry points 3 จุด

| | |
|---|---|
| **Type** | Design Task |
| **Priority** | High |
| **Fidelity** | Mid-fi |
| **Blueprint** | `features/gamification/ux-gamification.md` §2 §7 (D-03, D-04) |

### Description

ออกแบบ mid-fi ของจุดที่ทำให้ผู้ใช้รู้ว่ามีภารกิจ — ทั้ง 3 จุดต้องออกแบบ **ในบริบทของหน้าที่มันไปเกาะ** ไม่ใช่ลอยเดี่ยว ๆ เพราะต้องเห็นว่ามันไปแย่งพื้นที่กับอะไร

### Scope — 3 จุด + 1 modal

| ID | จุด | ไปเกาะที่ไหน |
|---|---|---|
| `MSN-001` | **Banner ภารกิจ** | หน้าแรก (ในบริบท carousel ที่มีอยู่) |
| `MSN-002` | **Icon ภารกิจ** | แถวบริการ (ปัจจุบันมี 8 รายการ) |
| `MSN-003` | **Popup ภารกิจสำเร็จ** | เด้งทันทีเมื่อทำภารกิจสำเร็จ ไม่ว่าอยู่หน้าไหน |
| `MSN-500` | Modal "เหลืออีกนิดเดียว" | เด้งเตือนคนที่ค้างภารกิจไว้ |

> `MSN-500` ใส่มาเพราะเป็น component ที่**เด้งหาผู้ใช้**เหมือนกัน ทำคู่กับ `MSN-003` จะได้ pattern ที่สอดคล้องกัน — ถ้าอยากตัดออกไปไว้ใบอื่นบอกได้

### Acceptance Criteria

- [ ] **AC1** ทุกจุดออกแบบ**ในบริบทของหน้าที่มันไปเกาะ** ไม่ใช่ component ลอย — ต้องเห็นว่าไปอยู่ตรงไหนของหน้านั้น
- [ ] **AC2** `MSN-002` แสดงแถวบริการ **หลังเพิ่ม icon แล้ว** (จะเป็น 9 รายการ) พร้อมข้อเสนอวิธีจัดการตาม D-03 — แทนที่ของเดิม / 2 แถว / scroll
- [ ] **AC3** `MSN-003` เด้งทันทีที่ภารกิจสำเร็จ · มีปุ่มปิดขนาดแตะได้ ≥44×44 px · มี CTA เดียวไปหน้ารายละเอียดภารกิจเพื่อกดรับรางวัล
- [ ] **AC4** `MSN-003` ระบุชัดว่า **ไม่แสดงบนหน้าใดบ้าง** (ผลของ D-04 — แนะนำยกเว้นตะกร้า/ชำระเงิน/กรอกข้อมูล แล้วเด้งเมื่อกลับมาหน้าปกติ)
- [ ] **AC5** `MSN-003` ต้องไม่เด้งซ้ำสำหรับภารกิจเดิมที่ผู้ใช้ปิดไปแล้ว
- [ ] **AC6** `MSN-500` copy มีช่องสำหรับ **ตัวเลขความคืบหน้าจริง** (เช่น "อีก 1 งวด") + ของที่รออยู่ + เวลาที่เหลือ + CTA เดียว — ห้ามใช้ข้อความลอย ๆ แบบ "อย่าลืมทำภารกิจ"
- [ ] **AC7** `MSN-003` กับ `MSN-500` ใช้ pattern เดียวกัน (ตำแหน่ง · ขนาด · ปุ่มปิด) แต่แยกกันออกด้วยเนื้อหา — ตัวหนึ่งคือ "สำเร็จแล้ว" อีกตัวคือ "ยังไม่เสร็จ"
- [ ] **AC8** ทุก frame ตั้งชื่อด้วยรหัส `MSN-xxx`

### Dependencies

| ต้องรอ | กระทบอะไร | ถ้ายังไม่ได้ |
|---|---|---|
| **D-03** icon ในแถวบริการ (จะมี 9 รายการ) | `MSN-002` · AC2 | 🟡 เสนอทางเลือกมาใน mid-fi แล้วให้ PO เลือก |
| **D-04** popup เด้งหน้าไหนได้บ้าง | `MSN-003` · AC4 | 🟡 ใช้สมมติฐาน "ยกเว้นหน้า critical" แล้วระบุไว้ |
| **OPEN-06** frequency cap ของ follow-up | `MSN-500` | 🟡 ไม่กระทบ layout |
| sitemap ปัจจุบันของหน้าแรก + แถวบริการ | AC1 · AC2 | 🔴 **ต้องได้ก่อน** — sitemap ที่มีลงวันที่ 2025-05-09 ถ้า production เปลี่ยนแล้ว บริบทที่วาดจะผิด |

→ **ต้องยืนยัน sitemap/หน้าแรกปัจจุบันก่อนเริ่ม** เพราะ ticket นี้ทั้งใบคือการวาดของใหม่ลงบนหน้าที่มีอยู่แล้ว

### Definition of Done

- Figma มี 4 frame ตั้งชื่อตามรหัส `MSN-xxx` โดยแต่ละอันแสดงในบริบทของหน้าจริง
- `MSN-002` มีข้อเสนอวิธีจัดการแถว 9 รายการอย่างน้อย 2 ทาง
- ระบุรายการหน้าที่ `MSN-003` ห้ามเด้ง
- ผ่าน review กับ PO 1 รอบ

## หมายเหตุที่ต้องบอกทีมพร้อมการ์ด

| # | เรื่อง | ทำไมต้องบอก |
|---|---|---|
| 1 | **ไม่มี onboarding ในรอบนี้** | ภาระการอธิบายตกมาที่ `MSN-201` + `MSN-210` ทั้งหมด (BP-10) — ถ้าหน้าเดียวอ่านไม่รู้เรื่อง ผู้ใช้จะออกโดยไม่เริ่มเลย · และ **อายุของรางวัลต้องย้ายมาอยู่ที่ `MSN-210`** เพราะไม่มีที่อื่นบอกแล้ว |
| 2 | **ยังไม่มี design system / component inventory** | designer ไม่รู้ว่า card / tab / bottom sheet / progress ที่มีอยู่หน้าตายังไง — mid-fi ใช้ greybox ไปก่อน แล้ว align ของจริงในรอบ hi-fi |
| 3 | **ยังไม่มี voice & tone** | copy ใน AC เป็นข้อกำหนดเชิงโครงสร้าง ไม่ใช่ final copy — UX Writer ต้องเข้ามาอีกรอบ |
| 4 | **`PHYSICAL` เป็น manual ผ่าน CRM และไม่มีหน้าติดตามในแอปเลย** | CRM ส่งสถานะกลับไม่ได้ — ผู้ใช้เงียบหายไปจนของถึงมือ (UX-06) · ยอมรับตั้งแต่ต้นว่าจะมีสายเข้า CRM จึงต้องทำให้การถาม**มีประสิทธิภาพ** (หมายเลขอ้างอิง + ปุ่ม LINE OA) ไม่ใช่พยายามกันไม่ให้ถาม |
| 5 | **ยังไม่มี SLA ของ `PHYSICAL`** | ห้ามใส่ตัวเลขวันที่เดาเอง (BP-09) — รอบแรกใช้ copy ที่ไม่ผูกวันที่ แล้ววัดจริงจากรอบนี้ค่อยกลับมาใส่ |
